# 学習マップ（v0.8.2）

[README](../README.md) · [English](CURRICULUM.en.md) · [操作ガイド](USER_GUIDE.md)

ThreatHunting-roomでは、**仮説 → 調査 → 根拠の整理 → 結論と限界 → 次の行動**という流れを練習します。不審な記録を見つけるだけでなく、正常な業務との比較、反証、観測できない範囲も扱います。

本編38問、別枠の操作チュートリアル1問・任意卒業演習X01、調査後の成果物9ステップを収録しています。A03・F01・F03の任意小体験は各2問、計6問で、本編の問数や完了条件に含めません。

## おすすめの進め方

最初に操作チュートリアルを進め、そのあと次の順で学ぶと、調査道具の使い方から自分のハント計画へ段階的に進めます。

**入門 → A → B → 練習 → E → C → 実践 → D → Linux → G**

章は自由に選べます。全問を一度に終える必要はありません。操作で迷ったらチュートリアルや入門へ戻り、調査の考え方で迷ったらヒントや解説を使ってください。

| 区分 | 学ぶこと |
| --- | --- |
| 操作チュートリアル | 画面の見方、検索、詳細表示、証拠、回答、振り返り |
| 第1部・入門 | 検索、仮説とデータ、集計、比較、関連記録の追跡、報告 |
| 第1部・練習 | 与えられた仮説を、必要なログと根拠で検証する |
| 第1部・実践 | 複数の手がかりをつなぎ、結論と限界を説明する |
| 第2部・A：可視性の棚卸し | 何が観測でき、何が欠けているかを整理する |
| 第2部・B：ベースライン | 普段の動きと比較し、珍しいが正当な活動も確かめる |
| 第2部・C：仮説の起点 | 脅威レポート、ATT&CKの技術、過去の事案、重要資産、検知の穴から仮説を作る |
| 第2部・D：調査の拡張 | 関連記録を広げ、同じ事案かどうかを切り分ける |
| 第2部・E：見つからなかったハント | 裏付けなしと観測不足を区別し、調査の価値と限界を残す |
| 第2部・L：Linux | 認証・権限・定期実行の合成ログを画面上で分析する |
| 第2部・G：次の計画 | 調査から次の仮説、優先順位、ハント計画につなげる |

第1部は独立したシナリオ、第2部は同じ架空企業の共通環境を使います。共通環境では同じ資産や通常業務を繰り返し参照できますが、課題ごとの評価範囲は固定です。資産台帳にあることと、必要なログが取得できることは同じではありません。

## 調査を成果物へつなげる

一部の練習・実践課題には、調査後に検知条件、引き継ぎ、可視性改善依頼などを作る段階があります。調査の完了と成果物の完了は別に記録します。

ハント記録は、仮説、起点、使用したログ、検索条件、結果、限界、次の行動に分けて書き出せます。共通環境を使う章では、棚卸しや仮説候補をまとめた「初めてのハント計画書」も作れます。途中段階の内容は、完了した調査結果と区別して扱ってください。

自由記述は模範例と比較して振り返るためのものです。文章の意味をAIが自動で評価したり、実組織向けの計画の妥当性を保証したりする仕組みではありません。

## 任意の小体験と「実務では」

調査を終えたA03、調査と成果物を終えたF01・F03では、「もう少し試す」から資料と2問を開けます。任意小体験の回答確認と完了は、本編・成果物とは別に記録します。誤答や未回答でも、完了済みの調査を保ったまま次の課題や復習へ進めます。旧版の進捗もそのまま読み込めます。

| 既存の課題 | 任意小体験で確かめること |
| --- | --- |
| A03：比較期間の途中で切れた記録 | 「起きた時刻と届いた時刻を分ける」：別の転送遅延の例で、イベントの発生時刻と取込時刻を比べ、起きた順と見えた順を区別する |
| F01：外部情報を環境の問いへ | 「同じ実行の記録を一つの候補にまとめる」：5行を端末・実行IDで2つの調査候補にまとめ、重複再送を新しい活動と数えない |
| F03：残された記録で調べる | 「改善した観測を別日のテストで確かめる」：ログ改善後に新たに分かる情報を読む。後日の取得が過去の欠測を復元するわけではないと確かめる |

C03では同一ハッシュの保管痕跡と、実行・後続活動の区別を明確にします。I06・C01・C05・G02の解説、およびP03・P04・F01の成果物の解説には、未採点の折りたたみ「実務では」があります。確認先の考え方、新しい証拠による再検討、引継ぎ後に残る問い、CTIや検知候補の適用範囲を短く紹介します。組織ごとの業務フローや責任移管を操作する課題は追加せず、ログ調査と根拠の判断を中心に体験します。

## roomシリーズでの位置づけ

ログや通信を読む基礎を身につけたあと、自分で問いを立てる練習へ進む教材です。SOCroomまでの学習を一通り経験してから取り組むとつながりを理解しやすくなりますが、ほかの教材の全問クリアは前提ではありません。

| 教材 | 復習したいこと |
| --- | --- |
| [Linuxroom](https://github.com/retiacole/linuxroom) | ファイル操作、検索、集計などのコマンドの基礎 |
| [SOCroom-easy](https://github.com/retiacole/socroom-easy) | 時刻・アカウント・結果などのログの読み方と調査操作 |
| [Logroom](https://github.com/retiacole/logroom) | Linux風コマンドを使うログの検索・集計・照合 |
| [pcaproom-easy](https://github.com/retiacole/pcaproom-easy) | パケット、プロトコル、通信の流れの読解 |
| [SOCroom](https://github.com/retiacole/socroom) | 複数の資料を使う調査、判断、報告 |

ThreatHunting-room自体にコマンド実行機能はありません。各roomの進捗や調査結果を直接インポートして引き継ぐ構成でもありません。身につけた操作や考え方を、別の教材の調査で使ってみてください。

## G02の後：任意の卒業演習 X01

本編の推奨順と38問の集計は維持します。X01は別枠の1問で、初見の3資産から起点を選び、仮説・比較・検索・反証・観測の限界・次の行動を自力でまとめます。手順や正解の仮説は指定しません。自己比較用の観点と複数の調査例は必要に応じて開けます。

提出には、両期間・2種類以上のログ・背景／反証／観測不足を含む4〜8件の注記付き証拠、再取得できる検索式、対象・期間・結論・限界・次の行動、現在の仮説と考察の自己比較が必要です。自動確認は構成と再現性に限り、結論や意味を採点しません。卒業演習を選ばず本編の復習を続けても構いません。
