# 操作ガイド

[README](../README.md) · [English](USER_GUIDE.en.md) · [学習マップ](CURRICULUM.md)

ThreatHunting-roomは、架空の環境と合成ログを使い、仮説を立てて確かめる練習をする教材です。実際の端末、ネットワーク、セキュリティ製品を操作するものではありません。

## はじめる

READMEの「すぐにやってみる」から開くか、オフライン用HTMLを保存してブラウザで開きます。JavaScriptを有効にしてください。ダウンロード済みのHTMLは単体で動作し、インストール、Webサーバー、APIキーは不要です。

進捗のない初回は、操作チュートリアルから始まります。案内された操作を済ませると、次の手順へ進めます。「操作場所を表示」で操作対象へ戻り、「中断して教材一覧へ」で中断できます。続きは教材一覧から再開してください。上部の「ガイド」からもチュートリアルを開けます。

## 表示言語

上部の **Language** で日本語・Englishを切り替えます。表示だけが切り替わり、進捗、入力中の検索式やメモ、ログ原文は共通です。ログの種類など、検索に使うデータの値には日本語が残る場合があります。

## 調査の流れ

1. **依頼を読む。** 対象の環境、期間、確かめる仮説、利用できるログを確認します。
2. **記録を調べる。** 検索で候補を絞り、集計・通常期間との比較・時系列で確かめます。端末や識別子をたどるときは、時刻と収集元も照合します。
3. **証拠を残す。** ハントノートに必要な記録を登録し、仮説に対する役割を選びます。
4. **結論をまとめる。** 求められた回答と理由を入力し、「証拠と回答を確認する」で振り返ります。ヒントと再挑戦による減点はありません。
5. **次の行動を考える。** 成果物の段階がある課題では、検知条件、引き継ぎ、可視性改善依頼などへ調査結果をつなげます。

証拠の役割は、単に「怪しい記録を集める」ための分類ではありません。

| 役割 | 残す理由 |
| --- | --- |
| 支持 | 調べている事実や仮説を裏付ける |
| 反証 | 正当な業務など、仮説と異なる説明を支える |
| 背景 | 通常時の状態や資産の役割など、判断に必要な文脈を示す |
| 観測不足 | 収集停止や対象外など、判断できない理由を示す |

正当な業務だと確認できること、調査範囲で裏付けが見つからないこと、ログ不足で判断できないことは別の結論です。検索結果が0件でも、活動がなかった証明にはなりません。

## 検索の基本

検索は教材専用の簡易構文です。KQLやSPL、OSのコマンドをそのまま実行する機能ではありません。

| 書き方 | 意味 |
| --- | --- |
| `process:powershell.exe parent:docview.exe` | 両方を満たす（空白はAND） |
| `destination:updates.example OR destination:portal.example` | どちらかを満たす（大文字のOR） |
| `sensor:edge-flow` | 特定のセンサーからの記録に絞る |
| `-process:powershell.exe` | 指定条件を除外する |
| `"複数の語句"` | 引用符内を一つの語句として検索する |
| `after:2026-09-14 before:2026-09-16` | 指定した両端の日を含むUTCの日付範囲 |

ANDをORより先に評価します。括弧によるグループ化には対応しません。画面で選んだログ種別・端末・期間などはORの全枝に適用されますが、検索式に書いた日付条件はそのORグループだけに適用されます。詳しい構文は画面の「検索の書き方」で確認してください。

集計と時系列は探索中の絞り込みを引き継ぎます。比較には独立した範囲があります。提出式の評価も、中央の探索画面とは別に表示された固定範囲で行われます。「探索中の式をコピー」は式だけをコピーするため、提出欄の評価範囲も確認してください。

### UTCとJST

ログ原文とCSVの時刻、検索式の`after:`・`before:`はUTCです。「JSTを併記」は日本時間も読みやすく表示する設定で、検索式の日付条件は変わりません。日付入力欄や報告の期間は、各欄のUTC／JST表示を確認してください。

第2部の共通環境では、調査期間と固定評価範囲はJSTの営業日です。画面の日付欄はJST／UTCを選べます。旧進捗に手動入力した日付はUTCとして保持され、検索式・メモ内の時刻は自動変換されません。新版の期間表示と照合して見直してください。

JSTはUTCより9時間進んでいます。たとえば9月15日JSTは、9月14日15:00 UTCから9月15日15:00 UTC未満です。同じ日付の表記でも、時間帯が異なると対象となる記録が変わります。

## 採点と振り返り

構造化した回答、必要なログ種別、証拠とその役割、必要な操作を確認します。無関係な記録を大量に加えても、正解にはなりません。

検索条件を提出する課題は、式の文字列ではなく、一致した記録の集合で評価します。検知条件を作る課題では、別の評価用ログに対する見逃しや余分な一致も確認します。表示される適合率・再現率は教材の標本に対する値です。

**自由記述の意味や報告の品質は自動採点しません。** 模範例と比べて、自分の判断を振り返ります。記述を変更したら、もう一度比較してください。単一HTMLには採点基準も含まれるため、回答を秘匿する試験システムではありません。

## 保存・読込・書き出し

| 操作 | 保存するもの | 用途 |
| --- | --- | --- |
| 上部の「保存」 | 進捗JSON | 別のブラウザや新版への持ち運び、バックアップ |
| 上部の「読込」 | 保存済みJSONを読み込む | 同じ課題の状態を置き換えて再開 |
| 「報告を保存」 | ハント記録のテキスト | 仮説・起点・使用ログ・検索条件・結果・限界・次の行動を振り返る |
| 計画書の保存 | ハント計画書のテキスト | 棚卸し、ベースライン、仮説候補、優先事項を整理する |
| CSV書き出し | 検索結果 | CSVに対応した手元の分析環境で確認する |

進捗はブラウザのlocalStorageにも自動保存します。保存できるかどうかはブラウザや組織の設定に依存します。ブラウザのデータ削除、別のブラウザへの移動、ローカルHTMLからWeb版への移動に備え、進捗JSONも保管してください。

読込は、同じ課題の進捗をファイルの内容に置き換え、現在の採点基準で完了状態を再計算します。読み込む前に現在の進捗を保存すると安心です。旧版で完了していても、改訂後に再確認が必要になる場合があります。

報告・計画書・CSVは進捗の復元用ファイルではありません。他のroomへの直接インポートにも対応していません。CSVにはカンマや引用符を含む値があるため、単純な文字列分割ではなくCSV対応の読み込み機能を使ってください。

「この課題をやり直す」は選択中の課題を初期状態に戻します。残しておきたい進捗や報告は先に書き出してください。

## 教材の範囲

合成ログは学習用の抜粋であり、実環境の全記録や発生率を表しません。Linux章も画面上でログを分析する構成です。実際のOSコマンド、ターミナル、パイプ、ネットワークへの操作を実行する機能はありません。

実組織のログや秘密情報を教材へ貼り付ける必要はありません。不具合を報告するときも、課題名、操作、ブラウザ名と教材の合成データで再現できる内容を使ってください。
